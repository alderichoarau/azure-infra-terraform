# terraform-managed-services

TP Java/Angular, piste "services managés": PostgreSQL Flexible Server,
Azure Managed Redis, Key Vault, Java Web App (backend, on the shared plan),
Angular Static Web App (frontend), and a Storage container on the shared
Storage Account.

Depends on `../terraform-core` (VNet, shared Storage Account, `ci_app_deploy`
identity — read via `terraform_remote_state`, see `main.tf`) and
`../terraform-shared-plan` (the App Service Plan, looked up by name via a
data source — no state coupling). Apply `terraform-core` first.

Independent of `../terraform-python` and `../terraform-aks-app` — this track
can be applied, destroyed, or left off entirely without touching either of
the other two, and vice versa.

## Important: shared with the AKS track

The Postgres and Redis instances created here are the SAME ones the "AKS"
track's backend deployment connects to (`azure-quiz-backend`'s
`deploy-aks.yml`, `SPRING_PROFILES_ACTIVE=aks`). That means this directory
must exist and be applied before the AKS track's backend can run — but it
stays a fully separate Terraform state from `../terraform-aks-app`, so the
two can each be created or destroyed on their own schedule without one
forcing the other. Don't destroy this directory while the AKS-track backend
is expected to keep working.

## Setup

1. `../terraform-core` must already be applied.
2. Create the HCP Terraform Cloud workspace `azure-managed-services-alderic-hoarau`,
   Execution Mode **Local**.
3. `terraform init && terraform plan` — review, then `terraform apply`.

## After applying

- Nothing manual needed for `backend_api_key`: `azure-quiz-frontend`'s
  `swa-deploy.yml`/`deploy-aks.yml` read the `backend-api-key` secret
  straight from Key Vault at deploy time (`az keyvault secret show`), not
  from a GitHub secret. `terraform output backend_api_key` is there for
  debugging only.
- `scripts/sync-app-secrets.sh` (repo root) pushes `AZURE_CLIENT_ID`/
  `AZURE_TENANT_ID`/`AZURE_SUBSCRIPTION_ID`/`AZURE_RG_NAME`/`AZURE_OWNER`
  into both app repos' GitHub secrets in one shot — usually not needed after
  the first setup, since only `AZURE_CLIENT_ID` changes across
  destroy/apply cycles, and `deploy-terraform.yml` already syncs that one
  automatically whenever `terraform-core` is part of the run.
