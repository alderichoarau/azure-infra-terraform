# terraform-core

Foundational, per-student resources: VNet + subnets + NSG, the shared Storage
Account, and the `ci_app_deploy` identity used by both app repos' CI. Every
other per-student directory (`../terraform-python`, `../terraform-managed-services`,
`../terraform-aks-app`) reads this directory's outputs via
`terraform_remote_state` instead of duplicating these resources.

## Why this exists as its own directory

Before this split, one monolithic `terraform/` directory held the network,
storage, CI identity, AND every track's app resources (Python App Service,
Java Web App, Postgres, Redis, ACR...) in a single state. That meant a
student who only wanted to try the "AKS" track still had to `apply` (and pay
for) the "managed services" track's Postgres/Redis/Key Vault, and vice versa
— everything was created or destroyed together.

Splitting the network/storage/identity out into `terraform-core` — applied
once, rarely touched — lets each track live in its own directory/state and be
applied or destroyed independently, while still sharing one VNet and one
Storage Account rather than each track provisioning its own.

## Who runs this, and when

You, first — before any track directory. Rarely touched afterwards (a new
subnet for a track still goes in that track's own directory, e.g.
`terraform-managed-services/database.tf`'s `subnet-data` — see that
directory's notes on the "one delegation per subnet" constraint).

## Setup

1. Create the HCP Terraform Cloud workspace `azure-core-alderic-hoarau` (or
   your own `azure-core-<owner>` if you're a student working from your own
   fork) in the `alderic-hoarau` org, Execution Mode **Local** (see
   `backend.tf`'s comment).
2. `terraform init && terraform plan` — review, then `terraform apply`
   (either locally with `-var="automation_only=true"`, or via this repo's
   GitHub Actions workflow).

## Consumed by

`../terraform-python`, `../terraform-managed-services` and
`../terraform-aks-app` each declare:

```hcl
variable "core_workspace_name" {
  type    = string
  default = "azure-core-alderic-hoarau"
}

data "terraform_remote_state" "core" {
  backend = "remote"
  config = {
    organization = "alderic-hoarau"
    workspaces   = { name = var.core_workspace_name }
  }
}
```

and reference `data.terraform_remote_state.core.outputs.<name>` — see
`outputs.tf` for the full list.
